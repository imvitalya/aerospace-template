# aerospace-template

Личный конфиг AeroSpace для MacBook и двух внешних мониторов. На каждом экране есть свои `interesting`, `hacking`, `main` и `other`. Имена пространств отражают расстановку экранов в настройках macOS.

| Подключенные экраны | Пример рабочих пространств |
|---|---|
| Два внешних рядом | `main-left` и `main-right` |
| Два внешних один над другим | `main-top` и `main-bottom` |
| Один внешний | `main` на внешнем |
| Встроенный экран MacBook | `main-mac` на ноутбуке, в том числе при подключенных внешних |

При перестановке откройте нужное пространство привычным хоткеем. Помощник также сверяет положение при старте AeroSpace и при смене сфокусированного монитора. Сопоставление работает и для двух одинаковых моделей. Для выбора горизонтали или вертикали сравниваются расстояния между центрами внешних экранов по X и Y. При равенстве выбирается горизонталь. Встроенный экран определяется через CoreGraphics. [AeroSpace 0.21.3-Beta](https://github.com/nikitabobko/AeroSpace/releases/tag/v0.21.3-Beta)

## Установка и обновление

Нужны macOS, запущенный AeroSpace 0.21.3-Beta и `python3` версии 3.8 или новее в PATH. Помощник использует стандартную библиотеку Python и штатный `osascript`.

```bash
git clone https://github.com/imvitalya/aerospace-template.git ~/aerospace-template
cd ~/aerospace-template
for file in aerospace.template.toml aerospace-render.sh aerospace-ws.sh aerospace-layout.py aerospace-screens.js; do
    cp "$file" "$HOME/.$file"
done
chmod +x ~/.aerospace-render.sh
~/.aerospace-render.sh
```

Для обновления повторите копирование файлов и запуск генератора. Если вы меняли четыре переменные `WS_*` в установленном генераторе, перенесите свои значения перед копированием. Горячие клавиши и параметры окон находятся в `aerospace.template.toml`. Генератор записывает `~/.aerospace.toml`, сохраняет предыдущий файл как `~/.aerospace.toml.backup.*` и восстанавливает его, если AeroSpace отклонил загрузку.

Чтобы узнать расположение дисплеев или подготовить отдельный TOML для конкретной расстановки, выполните в каталоге репозитория

```bash
/bin/bash aerospace-ws.sh layout
./aerospace-render.sh --output /tmp/aerospace-preview.toml --layout 'left=1 right=2'
```

Для автономного предпросмотра без аргумента `--layout` используется пример `top=1 bottom=2 mac=3`. При установке номера определяются по актуальным данным macOS и AeroSpace.

## Перестановка и отключение мониторов

При переходе с горизонтали на вертикаль окна из `*-left` попадают в `*-top`, из `*-right` — в `*-bottom`. При обратной перестановке они возвращаются в `*-left/right`. Скрипт сохраняет выбранную на каждом экране базу и исходное окно для операции переноса. При обновлении со старой версии он сначала проверяет, на каких экранах в действительности были закреплены `*-top` и `*-bottom`.

На единственном внешнем экране обе группы клавиш открывают общую базу, например `interesting`. Когда работает только ноутбук, окна временно собираются в `*-mac`. При возврате мониторов помощник восстанавливает сторону каждого окна и учитывает смену базы. Например, окно из `main-right`, перенесенное на ноутбуке в `other-mac`, возвращается в `other-right` при горизонтальной расстановке. Новые окна с ноутбука при закрытой крышке попадают на левый или верхний внешний экран.

Состояние хранится в `${XDG_STATE_HOME:-$HOME/.local/state}/aerospace/`. Файл `layout.json` содержит примененные назначения, `origins` запоминает стороны временно объединенных окон, `transition.json` позволяет продолжить прерванное перемещение по ID окон. Если расстановка прежняя, обычный хоткей использует уже загруженный конфиг. Для принудительной сверки запустите `/bin/bash ~/.aerospace-ws.sh sync --force`.

## Горячие клавиши

| Пространство | Открыть слева / сверху | Открыть справа / снизу | Перенести окно влево / вверх | Перенести окно вправо / вниз |
|---|---|---|---|---|
| `interesting` | `ctrl-cmd-s` | `cmd-shift-i` | `ctrl-alt-s` | `alt-shift-s` |
| `hacking` | `ctrl-cmd-h` | `cmd-shift-h` | `ctrl-alt-h` | `alt-shift-h` |
| `main` | `ctrl-cmd-m` | `cmd-shift-m` | `ctrl-alt-m` | `alt-shift-m` |
| `other` | `ctrl-cmd-o` | `cmd-shift-o` | `ctrl-alt-o` | `alt-shift-o` |

При старте открывается `main` на левом или верхнем внешнем экране, либо на доступном единственном экране. `cmd-j/k` листают базы слева или сверху, `ctrl-alt-cmd-j/k` — справа или снизу. Цикл идет от видимого пространства выбранного монитора в порядке `interesting → hacking → main → other`. Перенос по хоткею сохраняет фокус на исходном рабочем пространстве.

### Мониторы

| Клавиша | Действие |
|---|---|
| `ctrl-alt-j` / `ctrl-alt-k` | Перенести окно на соседний внешний экран вперед / назад по оси расстановки |
| `ctrl-alt-1` | Перенести окно на видимое пространство MacBook |
| `ctrl-alt-2` / `ctrl-alt-3` | Перенести на видимое пространство слева/сверху или справа/снизу |

**Конфликты.** AeroSpace перехватывает сочетания глобально, и до приложений они не доходят:
- `cmd-shift-h`, `cmd-shift-o`, `cmd-shift-m` в VS Code — замена по файлам, переход к символу, панель Problems;
- `alt-shift-<буква>` — ввод спецсимволов с клавиатуры.

### Остальное

| Клавиша | Действие |
|---|---|
| `alt-h` / `alt-j` / `alt-k` / `alt-l` | Фокус на окно слева / снизу / сверху / справа |
| `alt-shift-j` / `alt-shift-k` / `alt-shift-l` | Переместить окно вниз / вверх / вправо в раскладке (`alt-shift-h` занят переносом в `hacking-right` или `hacking-bottom`) |
| `alt-tab` / `alt-shift-tab` | Листать окна внутри воркспейса вперёд / назад |
| `alt-slash` | Layout: tiles (горизонтально/вертикально) |
| `alt-comma` | Layout: accordion (горизонтально/вертикально) |
| `alt-minus` / `alt-equal` | Уменьшить / увеличить окно |
| `alt-shift-space` | Переключить floating ⇄ tiling для окна |
| `alt-shift-;` | Войти в service-режим |
| `esc` (в service-режиме) | `reload-config` + выйти в основной режим |
| `r` (в service-режиме) | Сбросить раскладку (`flatten-workspace-tree`) |
| `f` (в service-режиме) | Переключить floating ⇄ tiling |
| `backspace` (в service-режиме) | Закрыть все окна воркспейса, кроме текущего |
| `alt-shift-h/j/k/l` (в service-режиме) | Объединить текущее окно с соседним в контейнер |

## Базовые имена и приложения

Четыре переменные в начале `~/.aerospace-render.sh` задают базовые имена. Например, можно заменить `WS_OTHER="other"` на `WS_OTHER="music"` и запустить генератор. Имена должны быть разными и состоять из латинских букв, цифр, `_` и `-`. Генератор сам дописывает нужный суффикс для текущей расстановки.

Все окна по умолчанию открываются в режиме `floating`, чтобы ими можно было управлять через Rectangle. Для отдельных окон доступен `accordion`. Примеры привязки приложений к первому внешнему экрану приведены в шаблоне. Добавляйте правила перед общим `{ if = 'true', run = 'layout floating' }`. AeroSpace применяет первое совпавшее правило, если явно не указан `check-further-callbacks = true`.

## Проверки

```bash
bash -n aerospace-render.sh
bash -n aerospace-ws.sh
python3 -m unittest discover -s tests -v
aerospace reload-config --dry-run --no-gui --warnings-as-errors
aerospace list-workspaces --monitor all --visible --format '%{workspace} | %{monitor-id}'
```

Тесты используют временный каталог и подстановки для AeroSpace и чтения экранов. Нативный dry-run проверяет установленный TOML.

# aerospace-template

Личный конфиг [AeroSpace](https://github.com/nikitabobko/AeroSpace) (тайлинг-менеджер окон для macOS) для MacBook и двух внешних мониторов, стоящих один над другим. Три идеи:

1. **Имена воркспейсов вынесены в переменные** — переименование не превращается в поиск по всему файлу.
2. **У каждого монитора свой набор воркспейсов**: `main-top` на верхнем, `main-bottom` на нижнем, `main-mac` на экране ноутбука. Суффикс в имени сразу говорит, где воркспейс.
3. **Без внешних мониторов окна «схлопываются»**: `main-top` и `main-bottom` собираются в `main-mac`, а когда мониторы возвращаются, окна разъезжаются по своим местам.

Используется с AeroSpace 0.21.3-Beta.

## Файлы

| Файл в репозитории | Куда копируется | Что это |
|---|---|---|
| `aerospace.template.toml` | `~/.aerospace.template.toml` | Шаблон конфига. Вместо имён воркспейсов — плейсхолдеры `__WS_SEARCH__`, `__WS_HACKING__`, `__WS_MAIN__`, `__WS_OTHER__`. Здесь правится вся логика: хоткеи, правила, привязка к мониторам. |
| `aerospace-render.sh` | `~/.aerospace-render.sh` | Генератор. Вверху — 4 переменные с базовыми именами воркспейсов. Подставляет их в шаблон, пишет `~/.aerospace.toml`, собирает индикатор и перезагружает AeroSpace. |
| `aerospace-ws.sh` | `~/.aerospace-ws.sh` | Помощник, через который идут хоткеи воркспейсов. Определяет, какие мониторы подключены, и схлопывает или раскладывает окна. |
| `aerospace-indicator.swift` | `~/.aerospace-indicator.swift` | Индикатор для меню-бара: показывает только воркспейс с фокусом. Собирается в `~/.local/bin/aerospace-indicator`. |

Не хранятся в репозитории:
- `~/.aerospace.toml` — генерируется, руками не редактируется (правки затрутся при следующей генерации);
- `~/.local/state/aerospace/` — состояние помощника: текущий режим и откуда пришли схлопнутые окна.

## Требования

- AeroSpace, установленный через Homebrew (`/opt/homebrew/bin/aerospace` — путь зашит в индикатор).
- Xcode Command Line Tools для сборки индикатора: `xcode-select --install`.
- Два внешних монитора друг над другом. Конфиг рассчитан на то, что в нумерации AeroSpace верхний монитор — 1, нижний — 2.

## Установка

```bash
git clone git@github.com:imvitalya/aerospace-template.git ~/aerospace-template
cd ~/aerospace-template
cp aerospace.template.toml ~/.aerospace.template.toml
cp aerospace-render.sh ~/.aerospace-render.sh
cp aerospace-ws.sh ~/.aerospace-ws.sh
cp aerospace-indicator.swift ~/.aerospace-indicator.swift
chmod +x ~/.aerospace-render.sh
~/.aerospace-render.sh
```

После установки:

1. Проверьте порядок мониторов: `aerospace list-monitors`. Верхний должен быть первым. Если нет — поменяйте местами `1` и `2` в `[workspace-to-monitor-force-assignment]` шаблона и в `monitor_suffix()` помощника.
2. Скройте значок AeroSpace в меню-баре (см. [Индикатор в меню-баре](#индикатор-в-меню-баре)).

## Воркспейсы и мониторы

Полное имя воркспейса — база и суффикс монитора:

| Суффикс | Монитор | Как AeroSpace его находит |
|---|---|---|
| `-top` | верхний внешний | номер 1 |
| `-bottom` | нижний внешний | номер 2 |
| `-mac` | встроенный экран | по имени, регулярка `built-in\|встроен` (на случай русской локализации) |

Номера мониторов AeroSpace считает по их расположению, а не по имени. Для двух одинаковых мониторов это единственный рабочий вариант: macOS называет их `PG27UCDM (1)` и `PG27UCDM (2)`, и эти номера с положением никак не связаны.

`*-top` и `*-bottom` — постоянные (`persistent-workspaces`). `*-mac` — нет: они создаются, когда нужны, и исчезают пустыми. Если бы они были постоянными, при закрытой крышке AeroSpace показывал бы их на внешних мониторах: назначение на встроенный экран ни с чем не совпадает, и такой воркспейс достаётся главному монитору.

## Режимы и «схлопывание»

Помощник определяет режим по крышке (`ioreg`, `AppleClamshellState`) и числу мониторов:

| Режим | Когда | Что происходит |
|---|---|---|
| `ext` | крышка закрыта | Работают `*-top` и `*-bottom`. Если в `*-mac` остались окна, они уезжают в `*-top`. |
| `mac` | крышка открыта, внешних мониторов нет | Окна из `<база>-top` и `<база>-bottom` переезжают в `<база>-mac`. Помощник запоминает, откуда пришло каждое окно. |
| `all` | крышка открыта, внешние подключены | Схлопнутые окна возвращаются, `*-mac` живут на экране ноутбука. |

Когда мониторы возвращаются, окно едет на свою позицию (top или bottom), но в ту базу, где лежит сейчас. Окно, которое на ноутбуке перенесли из `main-mac` в `other-mac`, уедет в `other-top` или `other-bottom`. Окна, открытые на ноутбуке, уходят в `*-top`.

**Когда помощник срабатывает.** Отдельного события о подключении мониторов в AeroSpace нет, поэтому проверка идёт:
- при каждом хоткее воркспейсов;
- при смене монитора с фокусом (`on-focused-monitor-changed`);
- при старте AeroSpace (`after-startup-command`).

Если отключить мониторы и ничего не нажимать, окна останутся на месте до первого хоткея.

**Самопочинка.** При закрытой крышке помощник при каждом вызове проверяет, что на мониторе 1 открыт `*-top`, а на мониторе 2 — `*-bottom`. Окна из воркспейсов вне схемы (например, временного «1», который AeroSpace создаёт для монитора без своих воркспейсов) переезжают на воркспейс, открытый на их мониторе.

Вручную разложить окна заново: `/bin/bash ~/.aerospace-ws.sh sync --force`.

## Горячие клавиши

### Воркспейсы

| Воркспейс | Клавиша | Перейти: верх | Перейти: низ | Перенести окно: верх | Перенести окно: низ |
|---|---|---|---|---|---|
| search | `s` | `cmd-ctrl-s` | `cmd-shift-s` | `alt-ctrl-s` | `alt-shift-s` |
| hacking | `h` | `cmd-ctrl-h` | `cmd-shift-h` | `alt-ctrl-h` | `alt-shift-h` |
| main (основной) | `m` | `cmd-ctrl-m` | `cmd-shift-m` | `alt-ctrl-m` | `alt-shift-m` |
| other | `o` | `cmd-ctrl-o` | `cmd-shift-o` | `alt-ctrl-o` | `alt-shift-o` |

Схема: `cmd` — перейти, `alt` (opt) — перенести окно; `ctrl` — верхний монитор, `shift` — нижний. Без внешних мониторов все четыре варианта ведут в `*-mac`. При переносе окно переезжает, а фокус остаётся на месте.

- **`main` — основной воркспейс**: при старте AeroSpace фокус переходит на `main-top` (или `main-mac`, если работает только ноутбук).
- **Цикл**: `cmd-j` / `cmd-k` листают воркспейсы верхнего монитора назад / вперёд, `ctrl-alt-cmd-j` / `ctrl-alt-cmd-k` — нижнего. Порядок: `search → hacking → main → other → (снова search)`. Без внешних мониторов обе пары листают `*-mac`. По умолчанию AeroSpace листает воркспейсы по алфавиту, поэтому порядок передаётся явно через `--stdin`.

**Конфликты.** AeroSpace перехватывает сочетания глобально, и до приложений они не доходят:
- `cmd-shift-s` — «Сохранить как» почти везде;
- `cmd-shift-h`, `cmd-shift-o`, `cmd-shift-m` в VS Code — замена по файлам, переход к символу, панель Problems;
- `alt-shift-<буква>` — ввод спецсимволов с клавиатуры.

### Мониторы

| Клавиша | Действие |
|---|---|
| `ctrl-alt-j` / `ctrl-alt-k` | Перенести окно на монитор ниже / выше |
| `ctrl-alt-1` / `ctrl-alt-2` / `ctrl-alt-3` | Перенести окно на ноутбук / верхний / нижний монитор |

### Остальное

| Клавиша | Действие |
|---|---|
| `alt-h` / `alt-j` / `alt-k` / `alt-l` | Фокус на окно слева / снизу / сверху / справа |
| `alt-shift-j` / `alt-shift-k` / `alt-shift-l` | Переместить окно вниз / вверх / вправо в раскладке (`alt-shift-h` занят переносом в `hacking-bottom`) |
| `alt-tab` / `alt-shift-tab` | Листать окна внутри воркспейса вперёд / назад |
| `alt-slash` | Layout: tiles (горизонтально/вертикально) |
| `alt-comma` | Layout: accordion (горизонтально/вертикально) |
| `alt-minus` / `alt-equal` | Уменьшить / увеличить окно |
| `alt-shift-space` | Переключить floating ⇄ tiling для окна |
| `alt-shift-;` | Войти в service-режим |
| `esc` (в service-режиме) | `reload-config` + выйти в основной режим |
| `r` (в service-режиме) | Сбросить раскладку (`flatten-workspace-tree`) |
| `f` (в service-режиме) | Переключить floating ⇄ tiling |
| `backspace` (в service-режиме) | Закрыть все окна воркспейса, кроме текущего |
| `alt-shift-h/j/k/l` (в service-режиме) | Объединить текущее окно с соседним в контейнер |

## Индикатор в меню-баре

Встроенный значок AeroSpace показывает все мониторы сразу, например `*main-top | main-bottom`, где `*` отмечает монитор с фокусом. Формат в конфиге не меняется. Индикатор показывает только воркспейс с фокусом — `main-top`: суффикс и так говорит, где фокус.

- Слушает `aerospace subscribe focused-workspace-changed`.
- Собирается `~/.aerospace-render.sh`, если исходник новее бинарника. Перезапускается при каждом рендере и при старте AeroSpace.
- Завершается вместе с AeroSpace, переподключается, если AeroSpace перезапустился. Одновременно работает один экземпляр.
- Клик по индикатору — меню с пунктом «Выйти».

Значок AeroSpace нужно скрыть самому: в настройках строки меню macOS или менеджером меню-бара (Ice, Hidden Bar и т.п.). Новый значок появляется левее всех, поэтому менеджер меню-бара может сразу спрятать сам индикатор — вытащите его, перетащив с зажатым `cmd`. Без значка AeroSpace конфиг перезагружается через service-режим: `alt-shift-;`, затем `esc`.

## Как переименовать воркспейс

1. Открыть `~/.aerospace-render.sh` и поменять значение переменной (например, `WS_OTHER="music"`).
2. Запустить `~/.aerospace-render.sh`.

Имя обновится везде: в `persistent-workspaces`, привязке к мониторам, хоткеях и правилах приложений. Суффиксы `-top`/`-bottom`/`-mac` добавятся сами. **Физическая клавиша при этом не меняется** — она закреплена в шаблоне и не зависит от имени. В имени допустимы латиница, цифры, `-` и `_`.

## Правила авто-раскладки приложений (`on-window-detected`)

Сейчас действует одно правило: все окна открываются плавающими (`layout floating`). Привязки приложений к воркспейсам лежат в шаблоне закомментированными примерами (Twilight → `main-top`; Happ, Telegram, Spotify → `other-top`).

Чтобы включить привязку, раскомментируйте строку и при необходимости поменяйте `-top` на `-bottom`. Если работает только ноутбук, помощник перенесёт такое окно в `*-mac` при следующем хоткее.

AeroSpace останавливается на **первом совпавшем** правиле (если не указан `check-further-callbacks = true`), поэтому привязки приложений должны стоять выше общего `{ if = 'true', run = 'layout floating' }`.

## Особенности конфигурации

- Все окна открываются как `floating`, а не в тайлинге — чтобы их можно было свободно ресайзить и двигать через Rectangle без того, чтобы AeroSpace «отжимал» размер обратно.
- `accordion` остаётся настроенным на случай, если понадобится вернуть тайлинг для части приложений.
- «Центр 80%» и «на весь экран» сознательно не забинжены в AeroSpace — эти хоткеи остаются за Rectangle.
- Хоткеи воркспейсов идут через bash-скрипт, это добавляет несколько десятков миллисекунд к переключению.

## Ограничения

- **Три экрана** (крышка открыта и оба внешних подключены):
  - номера мониторов считаются по расположению, и если встроенный экран окажется в нумерации раньше внешних, верх и низ сдвинутся;
  - хоткеев для переключения `*-mac` в этом режиме нет, окно на ноутбук переносится только через `ctrl-alt-1`.
- **Имя встроенного экрана** ищется регуляркой `built-in|встроен`. Если на вашей macOS оно другое, поправьте регулярку в шаблоне: имя показывает `aerospace list-monitors` при открытой крышке.

## Отладка

```bash
aerospace list-monitors                                              # порядок мониторов
aerospace list-workspaces --monitor all --visible --format '%{workspace} | %{monitor-id}'
aerospace list-windows --all --format '%{workspace} | %{app-name}'  # где какие окна
cat ~/.local/state/aerospace/mode                                    # режим, который видел помощник
/bin/bash ~/.aerospace-ws.sh sync --force                            # разложить окна заново
pgrep -fl aerospace-indicator                                        # жив ли индикатор
```

# aerospace-template

Личный конфиг [AeroSpace](https://github.com/nikitabobko/AeroSpace) (тайлинг-менеджер окон для macOS), собранный вокруг одной идеи: **имена воркспейсов вынесены в переменные**, чтобы переименование воркспейса не превращалось в поиск по всему файлу.

## Файлы

| Файл | Что это |
|---|---|
| `aerospace.template.toml` | Шаблон конфига. Вместо конкретных имён воркспейсов — плейсхолдеры `__WS_MAIN__`, `__WS_OTHER__`, `__WS_HACKING__`, `__WS_SEARCH__`. Редактируется тут вся логика: правила, хоткеи, порядок группировки. |
| `aerospace-render.sh` | Генератор. Вверху скрипта — 4 переменные с реальными именами воркспейсов. Подставляет их в шаблон и пишет результат в `~/.aerospace.toml`, затем перезагружает AeroSpace. |

`~/.aerospace.toml` — генерируемый файл, в репозитории не хранится и руками не редактируется (правки просто затрутся при следующей генерации).

## Установка

```bash
git clone git@github.com:imvitalya/aerospace-template.git ~/aerospace-template
cp ~/aerospace-template/aerospace.template.toml ~/.aerospace.template.toml
cp ~/aerospace-template/aerospace-render.sh ~/.aerospace-render.sh
chmod +x ~/.aerospace-render.sh
~/.aerospace-render.sh
```

## Как переименовать воркспейс

1. Открыть `~/.aerospace-render.sh`, поменять значение нужной переменной (например `WS_OTHER="music"`).
2. Запустить `~/.aerospace-render.sh`.

Готово — имя обновится везде разом: в `persistent-workspaces`, в хоткеях и в правилах авто-раскладки приложений. **Физическая клавиша при этом не меняется** — она закреплена в шаблоне один раз и не зависит от того, как воркспейс называется.

Если нужно поменять физическую клавишу или порядок группировки/цикла `cmd-j`/`cmd-k` — это правится в `aerospace.template.toml` (см. ниже, почему это два независимых понятия).

## Воркспейсы и горячие клавиши

| Воркспейс (сейчас) | Клавиша | Переключиться | Перенести окно сюда |
|---|---|---|---|
| search | `s` | `ctrl-s` | `ctrl-shift-s` |
| hacking | `h` | `ctrl-h` | `ctrl-shift-h` |
| main (основной) | `m` | `ctrl-m` | `ctrl-shift-m` |
| other | `o` | `ctrl-o` | `ctrl-shift-o` |

- **`main` — основной воркспейс**: при старте системы (`after-startup-command`) AeroSpace явно переключается на него, независимо от порядка ниже.
- **Группировка / цикл `cmd-j` / `cmd-k`**: `search → hacking → main → other → (снова search)`.
  `cmd-j` — на воркспейс назад (index-1), `cmd-k` — вперёд (index+1), с переносом через край.
  Это НЕ поведение AeroSpace по умолчанию: без явной настройки `workspace next/prev` крутит воркспейсы **по алфавиту**, а не в порядке из `persistent-workspaces`. Поэтому `cmd-j`/`cmd-k` в конфиге переопределены через `--stdin` с явным списком (см. `aerospace.template.toml`), а не через встроенную лёгкую команду.
- Физическая клавиша и позиция в цикле группировки — **независимые настройки**. Плейсхолдеры в шаблоне поэтому названы по роли (`__WS_MAIN__` и т.п.), а не по номеру позиции.

### Почему `ctrl-h`, а не `ctrl-c`

Изначально воркспейс назывался `coding` (клавиша `ctrl-c`), но `Ctrl+C` — это `SIGINT` в терминале (прерывание процесса), и глобальный перехват такого чувствительного chord'а слишком дорого обходится. Переименовали в `hacking` → `ctrl-h`: `Ctrl-H` в readline — это backspace, а его никто не жмёт как осознанный chord (все жмут физический Backspace), поэтому перехват почти ничего не ломает — как и с `ctrl-m` (readline это Enter, но опять же никто не набирает Enter через `Ctrl-M`).

`ctrl-s`/`ctrl-d`(бывший)/`ctrl-f`(бывший) тоже формально пересекаются с readline-биндингами (`Ctrl-S` — freeze терминала/forward-search, `Ctrl-D` — EOF), но это принятый компромисс — в отличие от `Ctrl-C`, потеря которого реально мешает прерывать зависшие процессы.

## Другие хоткеи

| Клавиша | Действие |
|---|---|
| `alt-h` / `alt-j` / `alt-k` / `alt-l` | Фокус на окно слева / снизу / сверху / справа |
| `alt-shift-h` / `alt-shift-j` / `alt-shift-k` / `alt-shift-l` | Переместить окно слева / снизу / сверху / справа |
| `alt-tab` / `alt-shift-tab` | Листать окна внутри текущего воркспейса вперёд / назад |
| `alt-shift-m` | Перенести весь воркспейс на другой монитор |
| `alt-slash` | Layout: tiles (горизонтально/вертикально) |
| `alt-comma` | Layout: accordion (горизонтально/вертикально) |
| `alt-minus` / `alt-equal` | Уменьшить / увеличить окно |
| `alt-shift-space` | Переключить floating ⇄ tiling для окна |
| `alt-shift-;` | Войти в service-режим |
| `esc` (в service-режиме) | `reload-config` + выйти в основной режим |
| `r` (в service-режиме) | Сбросить раскладку (`flatten-workspace-tree`) |
| `f` (в service-режиме) | Переключить floating ⇄ tiling |
| `backspace` (в service-режиме) | Закрыть все окна воркспейса, кроме текущего |
| `alt-shift-h/j/k/l` (в service-режиме) | Объединить текущее окно с соседним в контейнер |

## Правила авто-раскладки приложений (`on-window-detected`)

| Приложение | Bundle ID | Воркспейс |
|---|---|---|
| Twilight (Zen Browser) | `app.zen-browser.zen` | main |
| Happ | `com.happ.www` | other |
| Telegram | `ru.keepcoder.Telegram` | other |
| Spotify | `com.spotify.client` | other |
| Всё остальное | — | без привязки (просто floating) |

Правило срабатывает одинаково и для окна, открытого автозапуском при старте системы, и для окна, которое приложение открыло само — важен только `app-bundle-id`, а не то, кто его запустил.

**Важно:** AeroSpace обрабатывает правила `on-window-detected` по порядку и останавливается на **первом совпавшем** (если не указан `check-further-callbacks = true`). Поэтому привязки конкретных приложений в шаблоне идут выше общего `{ if = 'true', run = 'layout floating' }` — иначе до них просто не доходило бы дело.

Если открыть два окна одного и того же приложения (например два окна Twilight) — оба независимо попадут на один и тот же воркспейс: правило матчится по `app-bundle-id` каждого отдельного окна, а не по «инстансу» приложения.

## Особенности конфигурации

- Все окна открываются как `floating`, а не в тайлинге — чтобы можно было свободно ресайзить/двигать их через Rectangle без того, чтобы AeroSpace «отжимал» размер обратно.
- `accordion` остаётся настроенным на случай, если понадобится вернуть тайлинг для части приложений отдельными правилами `on-window-detected`.
- "Центр 80%" / "на весь экран" сознательно не забинжены в AeroSpace — эти хоткеи остаются за Rectangle.

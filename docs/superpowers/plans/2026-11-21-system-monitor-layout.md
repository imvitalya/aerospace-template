# Рабочие пространства AeroSpace по расстановке экранов в macOS

Цель — сохранить на каждом экране свои `interesting`, `hacking`, `main` и `other`. После перестановки экранов достаточно нажать привычное сочетание клавиш. Шаблон и скрипты устанавливаются один раз.

По согласованной схеме `Cmd+Shift+I` открывает `interesting` справа при горизонтальной расстановке и снизу при вертикальной. На другом экране в это время может быть открыт свой `interesting`.

## Что проверено 21 ноября 2026 года

На Mac работает AeroSpace `0.21.3-Beta`. CoreGraphics вернул следующие координаты. Названия и видимые пространства сверены с работающим AeroSpace.

| Положение | Экран macOS | Левый верхний угол | Видимое пространство |
|---|---|---|---|
| Слева | PG27UCDM (2) | `(0, 0)` | `main-top`, 2 окна |
| Справа | PG27UCDM (1) | `(2560, 0)` | `main-bottom`, 7 окон |

У обоих экранов размер `2560 × 1440` в системных координатах. Шаблон назначает все `*-top` на монитор № 1, все `*-bottom` на № 2. Помощник повторяет это правило в `monitor_suffix()`. Сам AeroSpace сортирует экраны сначала по левому краю, затем по верхнему. При вертикальной расстановке даже небольшой горизонтальный сдвиг может изменить нумерацию. [Сортировка в установленной версии AeroSpace](https://github.com/nikitabobko/AeroSpace/blob/d56e1637c3a1ed660d0cadd7534e94fb3218d1c3/Sources/AppBundle/model/Monitor.swift#L98-L106)

Имена пространств общие для всех мониторов. AeroSpace может показывать конкретное пространство только на одном экране одновременно. Поэтому для двух независимых `main` нужны два разных внутренних имени. [Правила AeroSpace для нескольких мониторов](https://nikitabobko.github.io/AeroSpace/guide#multiple-monitors)

## Поведение после перехода

| Расстановка | Первое сочетание, например `Ctrl+Cmd+S` | Второе, например `Cmd+Shift+I` |
|---|---|---|
| Два внешних рядом | `interesting-left` | `interesting-right` |
| Два внешних один над другим | `interesting-top` | `interesting-bottom` |
| Один внешний | `interesting` | `interesting` |
| Только MacBook | `interesting-mac` | `interesting-mac` |

Выбранные пользователем суффиксы отражают действительное положение внешнего экрана. При смене оси левая группа переходит в верхнюю, правая — в нижнюю и наоборот. Встроенный экран получает отдельный набор `*-mac`.

## Шаги реализации

### 1. Прочитать системную геометрию

- [x] Добавить небольшой `aerospace-screens.js` для штатного `osascript -l JavaScript`. Получать экраны из `NSScreen.screens`, их границы через `CGDisplayBounds`, признак встроенного — через `CGDisplayIsBuiltin`. Связать каждый экран с текущим `monitor-id` AeroSpace по `%{monitor-appkit-nsscreen-screens-id}`. В AeroSpace этот индекс начинается с 1. Сверка на обоих подключенных дисплеях прошла. [Формат list-monitors](https://nikitabobko.github.io/AeroSpace/commands#list-monitors) · [Глобальные координаты CoreGraphics](https://developer.apple.com/documentation/coregraphics/cgdisplaybounds%28_%3A%29)
- [x] Для двух внешних экранов сравнить абсолютные расстояния между центрами по X и Y. Если больше X, использовать суффиксы `left` и `right`. Если больше Y, использовать `top` и `bottom`. При равенстве выбрать горизонталь. В системе координат CoreGraphics Y растет вниз. Имена моделей, серийные номера и статус основного экрана в выборе роли не участвуют.
- [x] Научить `tests/fake_aerospace.py` отдавать номера мониторов и индексы AppKit из снимка. В `tests/test_helpers.py` проверить горизонтальную, вертикальную со сдвигом, диагональную и зеркальную расстановки, отрицательные координаты и MacBook левее двух одинаковых внешних мониторов. Зеркальная пара считается одним логическим экраном. Если система меняет список экранов прямо во время чтения, перечитать его и отложить переносы до согласованного снимка.

### 2. Применять назначения без ручной настройки

- [x] В `aerospace.template.toml` генерировать имена пространств с суффиксами текущей оси и `*-mac` для ноутбука. В `aerospace-render.sh` формировать `workspace-to-monitor-force-assignment` из найденных номеров. Постоянными объявлять доступные внешние наборы. У встроенного экрана использовать его текущий номер. Сохранить автономный `--output`, для предпросмотра конкретной расстановки принимать сохраненный снимок. Обновить список устанавливаемых файлов в `README.md`.
- [x] В `aerospace-ws.sh` проверять расстановку при старте, смене монитора с фокусом и перед хоткеями рабочих пространств и переноса между экранами. Даже при прежнем количестве дисплеев сравнивать координаты. При изменении геометрии сверять видимые пространства и обновлять направление команд. Перегенерировать локальный TOML и вызывать штатный reload только при изменении назначений или списка постоянных пространств. Использовать существующую блокировку `lockf` и отмечать назначения примененными после успешной загрузки. Повторный callback должен завершаться без новой записи.
- [x] Проверить в тестах перестановку двух включенных экранов с прежними именами, изменение только оси расстановки, повторный callback и ошибку reload с восстановлением конфига. Сравнить задержку хоткея до и после реализации. В пяти замерах запрос координат через `osascript` занимал от 85 до 96 мс за один вызов.

В этой версии AeroSpace есть событие смены сфокусированного монитора. Перестановка без смены фокуса обнаружится при ближайшем хоткее. Такой вариант обходится без отдельного фонового процесса и индикатора. [События AeroSpace 0.21.3](https://github.com/nikitabobko/AeroSpace/blob/d56e1637c3a1ed660d0cadd7534e94fb3218d1c3/docs/aerospace-subscribe.adoc)

### 3. Сохранить хоткеи и возврат окон

- [x] Перевести `focus`, `move`, `cycle`, `to-monitor`, `startup` и восстановление видимых пространств на динамические цели. Точка входа — `aerospace-ws.sh`, маршрутизация и журнал — в `aerospace-layout.py`. Для цикла и переноса на видимое пространство выбирать экран по текущему `monitor-id`. Для переноса фиксировать ID исходного окна до синхронизации. У двух внешних экранов `Ctrl+Option+J` переносит окно вправо или вниз, `Ctrl+Option+K` — влево или вверх. На краю окно остается на месте. `Ctrl+Option+1/2/3` выбирает ноутбук, левый/верхний или правый/нижний соответственно.
- [x] Для `interesting` проверить все четыре действующих сочетания. `Ctrl+Cmd+S` открывает левое/верхнее пространство, `Cmd+Shift+I` — правое/нижнее. `Ctrl+Option+S` и `Option+Shift+S` переносят окно в соответствующую сторону. `Cmd+Shift+S` свободно. Остальные базы используют свои текущие буквы.
- [x] При отключении одного из двух внешних мониторов собрать окна обеих сторон в одноименной базе на оставшемся мониторе. Когда остается только MacBook, собрать окна в `*-mac`. В журнале `origins` хранить исходную роль каждого перемещенного окна. Проверить переход «два внешних → один → ноутбук → два внешних». Окно, перенесенное на ноутбуке из `main-mac` в `other-mac`, должно вернуться на свою исходную позицию в группе `other`. Новые окна с ноутбука при закрытой крышке попадают в левую/верхнюю группу. Проверить также прерванный перенос и повторный `sync`.

### 4. Перенести текущие пространства и проверить результат

- [x] Перед установкой снять карту `window-id → workspace → monitor-id`, назначения старых пространств, видимые пространства и фокус. Сохранить шаблон, генератор, помощник, активный TOML и файлы состояния `mode` и `origins`. Под блокировкой сопоставить старые наборы с их фактическими экранами. Сегодня это `top → left` и `bottom → right`, то есть два окна в `main-left` слева и семь в `main-right` справа. При установке использовать свежий снимок. Если подключен только ноутбук, перевести исторические роли в журнале по правилу «верхняя → левая/верхняя, нижняя → правая/нижняя» и сохранить `*-mac`. Обрабатывать временные пространства после миграции известных баз.
- [x] Сделать перенос повторяемым. Сначала записывать исходное и целевое имя, затем перемещать окно по ID и проверять результат. После прерывания продолжать с оставшихся окон. Для отката восстановить файлы, назначения окон, видимые пространства и фокус по снимку.
- [x] До установки прогнать `python3 -m unittest discover -s tests -v`, `bash -n aerospace-render.sh`, `bash -n aerospace-ws.sh` и офлайн-предпросмотр. При установке проверить активный файл командой `aerospace reload-config --dry-run --no-gui --warnings-as-errors`. После установки сверить окна по ID и проверить хоткеи на подключенных мониторах. Вертикальную расстановку и возврат ноутбука дополнительно проверить на моделируемых системных снимках. Обновить в README таблицу клавиш и пример автоматической перестановки.

Критерий приемки — после смены расположения в настройках macOS первый `Cmd+Shift+I` открывает `interesting-right` или `interesting-bottom` на соответствующем экране. Второй экран в этот момент может показывать `interesting-left` или `interesting-top`.

## Результат реализации

На подключенных горизонтальных мониторах проверены `interesting-left` и `interesting-right` одновременно через `aerospace trigger-binding`. После проверки восстановлены прежние активные пространства и фокус. Восемь окон, открытых к моменту установки, сверены по ID и номеру монитора. Нативный dry-run прошел без предупреждений. 29 автоматических тестов включают вертикальную расстановку со смещением, возврат с MacBook и повтор после сбоя. Полная проверка двух горячих клавиш в работающем AeroSpace занимала около 0,3 с на вызов.
